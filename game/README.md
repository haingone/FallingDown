# FallingDown — P1 HD-2D 전환 프로토타입

> 지시문: `docs/instructions/P1_hd2d_conversion.md` / 기획서: `fallingdown_game_design.md` v2.0
> 스택: TypeScript + Vite + three.js (패키지 매니저: npm, lockfile 커밋)
> 이전 마일스톤: M1 3D 그레이박스 (`docs/reports/M1_report.md`, `M1_review.md`)

M1에서 검증된 코어 로직(입력 분류·속도 다이얼·게이지·도약·생애주기)을 그대로 이월하고,
**뷰와 판정만 HD-2D 다운 스크롤로 전환**한 프로토타입입니다. 실측 결과는 `docs/reports/P1_report.md` 참조.

## 실행

```bash
cd game
npm install
npm run dev        # 개발 서버 (기본 http://localhost:5173, --host 로 LAN 노출됨)
```

- 데스크톱: 마우스 드래그 = 스와이프, 클릭 = 탭 (터치와 동일 처리)
- **폰에서 접속**: `npm run dev` 실행 후 터미널의 `Network:` 주소(예: `http://192.168.x.x:5173`)를
  같은 Wi-Fi의 폰 브라우저로 엽니다. 원격/클라우드 환경이라면 `npm run build` 후 `dist/`를
  정적 호스팅(GitHub Pages, Netlify 등)에 올려 URL로 접속하세요 (순수 정적 빌드, 서버 불필요).

## 빌드 / 테스트

```bash
npm run build      # 타입체크 + dist/ 정적 빌드 (gzip 약 136KB)
npm run preview    # 빌드 결과 로컬 서빙
npm test           # Playwright 자가 검증 22개 (입력·2D 동선·게이지 A/B·시퀀스·성능·UI)
```

사전 설치된 Chromium(`/opt/pw-browsers/chromium`)을 사용합니다. 다른 환경에서는
`FD_CHROMIUM=<chrome 경로>`로 지정하거나 `npx playwright install chromium` 후
`playwright.config.ts`의 `executablePath` 지정을 제거하세요.
실행 후 `test-results/`에 실측 지표(JSON)와 스크린샷이 남습니다.

## 조작

| 입력 | 동작 |
|---|---|
| 탭 (이동 <24pt & <200ms) | 우산 접기/펼치기 토글 — 접음=가속·우산 베기, 펼침=감속·검 베기 |
| 스와이프 (이동 ≥24pt 또는 ≥0.5pt/ms) | 베기 — 판정 링 안(하이라이트+비프음)의 적만 벨 수 있음 |
| 하단 게이지 버튼 탭 | 게이지 100% 시 도약 (2.5초 무적, 적 밀집 지점으로 비행) |

적은 **화면 하단·사선 하단에서 진입해 위로 지나갑니다**(낙하 중이므로). 소녀 주변 판정 링에
들어온 순간에만 벨 수 있습니다.

## 튜닝 패널

우측 상단 ⚙ 버튼으로 열립니다 (`?debug=0`으로 숨김). 실기기 검증 시 이 패널의 수치를 읽어 주세요.

- **통계**: FPS / 1% low / draw call / 오버드로우 추정, 입력 분류 카운트와 오분류 의심률,
  게이지 100% 도달 시각·판당 도약 횟수, 오디오 지연(WebAudio base/output)
- **주요 손잡이**: 탭/스와이프 임계, 가감속률, 판정 링 반경(화면 폭 비), 소녀 세로 위치,
  체류·공격주기 배수, 체류형 선회 반경·배치각(혼잡도), 스탠스 궤적 폭·재판정 간격,
  히트스톱·베기 궤적 잔광, 스크롤 속도·줌·셰이크, 3D 오브젝트 밀도,
  **게이지 배율 A/B 토글**, **픽셀 스케일링 정책**(네이티브 ↔ 저해상도→정수배)

## 구조 (로직-렌더링 분리)

```
src/core/     # 순수 TS — three.js/DOM 미참조 (엔진 교체 대비 이식 가능 계층)
  balance.ts    # 기획서 v2 7~11장 수치 단일 데이터 모듈 (패널이 이 객체를 실시간 수정)
  sim.ts        # 시뮬레이션: 속도 다이얼·2D 동선·링 판정·게이지·도약·웨이브·HP
  classifier.ts # 탭/스와이프 분류기 (M1 이월, 오분류 0% 검증)
  field.ts      # 2D 플레이 평면 ↔ 화면 좌표 매핑 (M1의 원근 투영을 대체)
  runner.ts     # 고정 타임스텝(120Hz) + 렌더 보간
  rng.ts        # 시드 RNG
src/data/     # waves.json — 90초 웨이브 시퀀스 (코드와 분리된 데이터)
src/render/   # HD-2D 렌더러·베기 궤적 셰이더·플레이스홀더 스프라이트·HUD·패널·비프음·FPS
tests/        # Playwright 자가 검증 (helpers.ts에 대기 조건 보강)
```

### HD-2D 레이어 (기획서 v2 4장)

2패스 합성입니다. 판정은 전부 ④ 평면에서만 이루어지며, ①~③은 순수 연출입니다.

| 패스 | 카메라 | 레이어 |
|---|---|---|
| 1 | 원근 | ① 스카이 그라데이션 + 구체 ② 패럴랙스 구름 3겹 ③ 3D 오브젝트(부유 유적 3종) |
| 2 | 직교 | ④ 게임플레이 2D 평면(소녀·적·투사체·판정 링) ⑤ 전경(속도선·파편·베기 궤적) |

직교 카메라의 프러스텀·줌은 `core/field.ts`의 좌표 매핑과 정확히 일치시켜, 화면에 보이는 위치와
스와이프 판정 위치가 어긋나지 않도록 했습니다. 적·투사체·파티클·궤적은 전부 오브젝트 풀링입니다.

에셋 파일은 하나도 없습니다 — 소녀·적 스프라이트는 런타임 캔버스 실루엣, 베기 궤적·스카이는 셰이더,
유적은 프리미티브 조합, 사운드는 WebAudio 합성음입니다.
