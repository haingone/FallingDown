## 1. 전환 사유 (사용자)

> "3D 캐릭터 애니메이션과 카메라 조정, 그리고 플레이의 융합이 쉽지 않을 것 같고, 밸런스를 맞추다가 게임의 재미를 놓쳐버릴 것 같다."

**AD 소견: 근거 있는 우려로 판단한다.** 개발 계획서 8장은 이미 "glTF 스킨 애니메이션 파이프라인(Blender/Tripo → three.js)"을 리스크로 등재했고, 본 세션의 아트 탐색 5라운드가 전부 **카메라·자세·크롭 문제**로 반려·재작업된 것 자체가 그 난이도의 실증이다. 3D 캐릭터를 화면에서 성립시키는 데 아트 리소스가 과도하게 소모되었고, 그 시간은 재미 검증에 쓰이지 못했다.

## 2. 새 방향 정의

**2.5D — 게임플레이 요소는 2D 픽셀 아트, 배경 일부만 3D.**

| 레이어 | 형식 | 내용 |
|---|---|---|
| 캐릭터 (소녀) | **2D 픽셀 아트, 2등신** | 낙하·베기·도약·피격 스프라이트 |
| 몬스터 (A/B계열, 보스) | **2D 픽셀 아트** | 거리 단계별 스프라이트 |
| 까마귀 | **2D 픽셀 아트** | 6종 수집 요소 |
| 이펙트·UI | **2D 픽셀 아트** | 참격, 폭발, HUD, 판정 링 |
| 배경 | **3D 일부 + 2D** | 구름 터널·부유 오브젝트 소수를 3D로, 약간의 카메라 무빙 |

## 4. 새로 생기는 문제 (반드시 선결)

### 4.1 ~~픽셀 아트 × Z축 원근~~ — **철회 (2026-08-26)**

> AD가 카메라를 오해해 제기했던 쟁점. 사용자 정정으로 **소멸**했다.
>
> **정정: 이번 방향은 Z축(깊이) 낙하가 아니라, 정측면 카메라에서 Y축(화면 세로)으로 떨어지는 구도다.**
>
> 깊이 방향 확대가 없으므로 스프라이트를 스케일할 일이 없고, 픽셀 퍼펙트가 자동으로 유지된다. LOD·정수배 스케일 논의는 불필요하다.

### 4.2 ⚠ 인터뷰 1회차 결정과의 충돌

인터뷰에서 확정했던 캐릭터 방향이 무효화된다.

| 인터뷰 확정 사항 | 2등신 픽셀에서의 상태 |
|---|---|
| "캐릭터 비율 **5~6등신 이상**" | **폐기** — 2등신으로 전환 |
| "소녀 = **멋진 스타일** 담당" | **재정의 필요** — 2등신 SD는 귀여움 축 |
| "귀여움·캐주얼은 **까마귀가 담당**" | **역할 분담 붕괴** — 소녀도 귀여움 축으로 이동 |
| "캐주얼하되 **성인 소구**" | 유지 가능 — 픽셀 아트는 성인 인디 게임 관객에 강함 |
| "AI 웜/황변 톤 금지, 디즈니·픽사 금지" | 유지 |
| "스테이지별 팔레트, 스타일리시·화려" | 유지 — 픽셀에서도 성립 |

**결정 완료 (2026-08-26): 1번 채택.**

> **캐릭터는 SD 체형으로 귀엽게, 액션을 멋지게 표현한다.** (사용자 제시 레퍼런스: 산나비)

- 소녀의 매력 = **귀여운 몸 + 멋진 액션**. 두 축을 한 캐릭터가 동시에 담당한다.
- 멋짐의 전달 매체는 캐릭터 조형이 아니라 **모션·이펙트·연출**이다 — 참격 궤적, 잔상, 히트스톱, 화면 연출, 극적인 림라이트.
- 까마귀와의 역할 분담 재정의: **소녀 = 액션 / 까마귀 = 마스코트·수집**. 소녀가 귀여움 축으로 이동해도 까마귀는 "더 둥글고 작고 무해한" 조형으로 차별화한다.
- 인터뷰의 "성인 소구, 유아용 인상 금지"는 유지 — 시네마틱 연출과 어두운 무드가 이를 담보한다.

### 4.3 기타

- **까마귀와의 차별화:** 소녀도 2등신이면 까마귀와 실루엣이 유사해질 수 있다. 까마귀는 더 둥글고 작게, 소녀는 코트·우산의 각진 실루엣으로 구분.
- **적 실루엣 1프레임 식별(기획서 17.3)**은 픽셀 아트에서 오히려 유리하다 — 저해상도가 실루엣 단순화를 강제한다.
- **3D 배경과 2D 스프라이트의 접합:** 픽셀 스프라이트와 매끄러운 3D 배경이 섞이면 이질감이 생길 수 있다. 배경도 디더링·포스터라이즈 후처리로 픽셀 톤에 맞추는 셰이더가 필요할 수 있다 — 이펙트 예산에 반영.

## 7. 카메라 규격 정정 (2026-08-26) — **정측면 / Y축 낙하**

> 사용자 정정: **"이번 아트 방향성은 z축으로 떨어지는 게 아니라, 그냥 정측면 카메라 뷰에서 y축으로 떨어지는 상황을 그리는 거다."**

AD가 이전 3D 방향의 Z축 구도를 그대로 끌고 와 오해했다. 본 절이 정본이다.

### 확정 카메라

| 항목 | 내용 |
|---|---|
| 시점 | **정측면 (side view)** — 평면 직교에 가까운 옆모습 |
| 낙하축 | **Y축 (화면 세로)** — 소녀는 화면 아래로 떨어진다 |
| 소녀 위치 | 화면 상단~중단의 고정 위치, 좌우로 약간 이동 |
| 배경 | 세로로 위쪽으로 흐름(패럴랙스 다층). 3D 오브젝트가 섞여 약간의 카메라 무빙 |
| 원근 | **없음** — 소실점·단축·깊이 스케일 전부 불사용 |

### 이 정정이 바꾸는 것

**해소되는 문제**
- 픽셀 × 깊이 스케일 충돌 (4.1) — 소멸
- 3D 카메라 상태 머신, FOV 조정, 판정 링 디스크 투영 — 전부 불요
- 본 세션 5라운드를 태운 "캐릭터 자세·크롭·카메라" 문제군 — 근본 소멸

**새로 정의해야 하는 것**
1. **판정 영역:** 기존 "소녀 주변 판정 링(Z 깊이면)"이 성립하지 않는다. 정측면에서는 **소녀 주위의 원형 판정 범위** 또는 **화면 가로 밴드**가 후보. 스와이프가 2D 화면 좌표에서 직접 판정되므로 구현은 훨씬 단순하다.
2. **적 동선:** 기존 "원경 소실점에서 Z축으로 접근"이 성립하지 않는다. 정측면에서는 **화면 아래에서 위로 올라오거나, 좌우 가장자리에서 진입**한다. 기획서 10.0(통과형/체류형) 정의를 2D 동선으로 재작성해야 한다.
3. **속도 표현:** FOV 확장 대신 **배경 스크롤 속도 + 세로 속도선 + 모션블러 + 화면 흔들림**으로.
