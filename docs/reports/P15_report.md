- 흔들림 프레임은 낙하 루프로 재생 (fps 6, 3프레임 순환 — manifest의 `animation.rows[*].fps` 사용).

### 1.2 로더를 실제 스키마에 맞춰 좁혔다

P1.5 1차(§B-1)에서는 Sprite-Gen 출력 스키마를 몰라 관용 파싱만 해 두었다. 실산출물 확인 후 **정본 경로를 추가**했다:

- 시트: `sprite_sheet_alpha` → `game_input` → (기존 관용 키)
- 프레임 사각형: **`frame_layout.rows[클립명]`** (정확한 rect 배열) 최우선
- fps: `animation.rows[클립명].fps`
- 셀 크기: `animation.cellWidth/Height` → `frame_layout.*` → `cell.width/height`
- 폴더가 `girl/`·`enemies/` **2벌로 나뉘므로 다중 소스 로드**로 확장 (1차 구현은 단일 manifest 가정이었다)

기존 관용 파싱(배열/row·count/키 별칭)은 회귀 테스트로 유지했다 — 다른 산출 경로가 와도 읽힌다.

### 1.3 방향 보정

AD README 3번 편차("적은 좌향, 소녀는 우향")를 프레임 메타 `facing`으로 처리했다.
통과형은 진행 방향으로 회전하는데, 그림이 향하는 방향만큼 빼서 보정한다:

| 대상 | facing | 결과 |
|---|---|---|
| 반입 적 스프라이트 | π (좌향) | 상승 방향으로 정확히 회전 |
| 실루엣 폴백 | π/2 (상향) | 기존 동작 유지 |
| 소녀 | (회전 없음) | 우향 그대로 |

## 2. §B-3·4 이펙트·배경 팔레트 적용

색상값은 `src/render/palette.ts` 한 곳에 모았다 — **코드 어디서도 hex를 직접 쓰지 않는다.**

### 2.1 점등 규칙 교체 (핵심)

민트 하이라이트(`#59FFA8`)를 **폐기**하고 `fx_palette §2.5`의 명도 규칙으로 바꿨다.

| 상태 | 구현 |
|---|---|
| 판정 영역 진입 | 대상 **자기 색의 명도 ×1.45** + 뒤에 확대 실루엣(×1.16, α0.6) = 외곽 발광 |
| 공격 예고 | 명도 ×1.8 + 발광색만 **바이올렛 `#8A5CD8`**(적 액센트 예약) |

**어떤 요소도 점등 시 새 색상을 얻지 않는다**는 원칙을 지켰다. 반입 스프라이트는 자체 색을 가지므로
무틴트(흰색)로 그리고 명도 배수만 곱한다 — 타입 색으로 틴트하면 픽셀 아트가 어두워지기 때문이다.

### 2.2 요소별 적용

| 요소 | 적용 |
|---|---|
| 베기 궤적 | **우산·검 모두 콜드 시안 계열** — 구분은 색이 아니라 형태(넓은 호 vs 가는 선). 우산 `#3C81A2`, 검 `#63DCE3`, 코어 화이트 |
| 격파 플래시 | 화이트 단색 (임팩트 코어 예약) |
| 격파 파편 | 적 본체 색 `#1D2C51`·`#23476C`·`#214066`에서 채취, **20%만 `#3C81A2`로 명도 점프** |
| 밴드 라인 | 평상 `#24274D` α35% 1px / 적 진입 `#3C81A2` α70% + 외곽 발광 / 격파 `#63DCE3` α100% **2px** |
| 속도선 | `#707DA2`(저속) → `#3C81A2`(고속), α25~55%, **화면 중앙 40% 클린** |
| 소녀 피격 | **핫 마젠타 `#E60986`** (마젠타 예약의 유일한 예외) |
| 3D 오브젝트 | `#131B3C` 본체 / `#23476C` 엣지 (범위 외 — 색만 예약 적용) |

### 2.3 배경 (background_p15)

- **스카이 5단 밴딩** — 셰이더로 단을 눈에 보이게 끊고, 각 경계에 1px 체커 디더. 낙하에 따라 전체가 위로 스크롤.
- **구름 2장** — 원경 `#1F3157` α40% 패럴랙스 0.25× / 근경 `#21395F` α55% 0.55×.
  텍스처를 **가로로 긴 둥근 사각 덩어리**로 다시 그렸다 (기존 소프트 방사 블롭 → 스펙의 "사실적 구름 금지" 반영), 상하 경계 1px 디더.
- **캐릭터 뒤 소프트 비네트** `#0C0F25` 중심 α45% → 가장자리 0, 반경 화면폭 25%. **상시 ON, 끄지 않는다**
  (배경 명도 분리 = 가독성 필수 요소).

### 2.4 발견·수정한 결함 ①: 밴드 라인이 안 보이던 문제

스펙의 "1px 라인"을 밴드 높이 대비 비율(smoothstep)로 그리고 있었다. 밴드가 257px 높이라
"경계"가 **15px짜리 소프트 그라데이션**으로 퍼졌고, α35%의 어두운 색이 화소당 대비를 잃어 사실상 보이지 않았다.

→ `fwidth`로 UV→화면 픽셀을 환산해 **실제 픽셀 두께 라인**(평상 1px / 격파 2px)으로 다시 그렸다.
격파 플래시도 내부를 채우는 대신 **라인이 두꺼워지고 밝아지는** 방식으로 바로잡았다 (스펙 §2.4 문언 그대로).

## 3. §B-5 용량 실측 (에셋 최초 반입 시점 기준선)

| 항목 | 크기 |
|---|---|
| JS 번들 | 541.9 KB (**gzip 143.8 KB**) |
| index.html | 5.3 KB (gzip 1.9 KB) |
| **스프라이트 에셋** | **11,429 B** (girl 시트 5,956 + enemies 시트 1,938 + manifest 2종 3,535) |
| **dist 총합** | **560,238 B** (547 KB) |

- 계획서 2.1 예산 대비: 코드+엔진 3MB 대비 gzip 143.8KB로 여유가 크다.
  스프라이트 시트 예산 25MB 대비 현재 **7.9KB**(PNG만) — 캐릭터 1종·적 2종·최소 프레임 기준의 출발점이다.
- **Sprite-Gen 이력 파일은 배포본에서 제외했다.** `sprite-request.json`·`*.report.json`은 저장소에 남기되
  런타임이 읽지 않으므로 번들에서 빼, 스프라이트 페이로드를 16,388 B → **11,429 B (-30%)** 로 줄였다.

## 4. 밸런스 불변 검증 (HQ 요구사항)

"스프라이트 적용으로 히트박스 수치가 변하지 않아야 한다"를 **자동 검증**으로 못박았다.

- 적을 밴드 안 고정 위치에 두고 **판정이 닿는 최대 수직 거리를 이분 탐색**으로 측정,
  스프라이트 반입 **전후 값이 소수점 2자리까지 동일**함을 확인.
- 기획서 수치 회귀도 함께 확인: 우산 궤적 폭 34pt / 링 반경 0.33 / 밴드 높이 0.66.
- 근거: 히트박스는 `core/sim.ts`의 `ENEMY_DEF.hitRadius`(필드 단위 상수)이고 스프라이트는
  **표시 크기·종횡비만** 바꾼다. 코어는 여전히 three.js를 import하지 않는다 (0건).

### 4.3 발견·수정한 결함 ②: 0 피해가 피격으로 처리되던 문제

측정용으로 `contactDamage=0`을 쓸 때, `damagePlayer(0)`이 HP는 그대로 두면서도
**무적 타이머·피격 이벤트·콤보 리셋을 발동**시켰다. 그 결과 전체 화면 피격 플래시가 계속 떠
스크린샷이 붉게 물들었고(초기 캡처본에서 발견), 측정 조건도 오염됐다.

→ `dmg <= 0`이면 피격으로 치지 않도록 코어를 수정했다. 실제 플레이(피해 1)에는 영향이 없다.

## 6. 편차·우려 사항

### 6.1 우려 ① — 평상시 밴드 가독성 (판단 요청)

스펙대로 평상 밴드를 `#24274D` α35% 1px로 그리면 **어두운 배경에서 거의 보이지 않는다**.
적이 밴드에 들어오면 `#3C81A2` α70% + 외곽 발광으로 확실히 살아나므로 "평상 = 조용, 진입 = 점등"이라는
의도는 성립한다. 다만 P1 실기기 판정에서 밴드가 **"언제 벨 수 있는가"를 1프레임에 읽히게 하는 타이밍 축**으로
채택된 만큼, 적이 없을 때 판정 영역의 위치 자체가 안 보이는 것이 맞는지 확인이 필요하다.

- 스펙 재해석은 하지 않았다 — **문언 그대로 구현**하고 여기 보고한다.
- 조정이 필요하면 손잡이는 두 개다: 평상 알파(35%↑) 또는 평상 색 명도(`#24274D` → 한 단 위).

### 6.2 편차 — AD README에 기재된 항목 (개발 측 조치 없음)

1. **적 스프라이트의 1px 다크 아웃라인** — AD 보고된 계약 불일치. 실사용상 문제 없다는 AD 판단에 동의하며,
   해소는 P2 재생성 시.
2. **`fall_open` 흔들림 2프레임은 절차적 생성물** — P1.5 "미세 흔들림" 범위 내로 이해했다.

### 6.3 구현 판단 (보고 대상)

1. **적 회전 유지** — AD "필요한 쪽을 플립해 쓴다"를 **진행 방향 회전 + facing 보정**으로 구현했다
   (상승하는 적이 위를 향한다). 단순 좌우 플립이 의도였다면 알려 달라 — 1줄 변경이다.
2. **격파 고스트는 현재 프레임 텍스처를 승계** — 반입 스프라이트가 그대로 화이트아웃·스케일 팝된다.
3. **Sprite-Gen 이력 파일 번들 제외** (3장) — 저장소에는 남는다.
