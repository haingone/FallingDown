## 2. 작업 범위 (이 지침의 산출물)

### N1-1. 캐릭터 시트 v1 확정판 (승인 게이트)

- CS1/CS2 갱신: **V2 마젠타 주 + C 하이브리드 얼굴** 반영, 2등신 엄수. 표정 4종(평상·결의·놀람·피격), 접음(우산)/펼침(검) 2스탠스, 낙하 기본 자세.
- 아웃라인 없음 전제의 가독성 3축(액센트 면적 / 림라이트·글로우 / 배경 명도 분리)을 시트에 명문화하고, **48×48 상당 축소본을 어두운/밝은 배경 2종에 올린 가독성 테스트**를 포함할 것 (E1 검증 방식 유지).
- 게이트: 사용자 최종 승인. 승인본이 이후 모든 생성의 고정 레퍼런스가 된다.

### N1-2. 까마귀 6종 보강판

- 1장의 보강 조건 2건 반영 + 텍스트 렌더 제거(GAVEWIND 오기 등). 최하단 실루엣 행에서 6종이 흑백으로도 구분되면 통과.

### N1-3. 목업 재생성 — 드리프트 종결

- N1-1 승인본을 레퍼런스로 물려 인게임 목업 재생성: 낙하(평상) / 전투(베기 궤적) / 도약 3장 내외. 판정 표현은 C1 확정 전이므로 **두 방식 중 임의 선택 + "가안" 표기**.

### N1-4. 스프라이트 시트 사양서 v1 (`docs/art/sprite_spec.md`)

- 확정 사양 고정: 48×48, 32~48색 **run 공유 팔레트**, 아웃라인 없음, 프레임 정책(평상 2~4 / 액션 6~12 혼용).
- 애니메이션 리스트: 기획서 v2.0 기준으로 소녀(낙하 루프, 토글 전환, 우산 베기, 검 베기, 피격, 도약 진입·루프·종료)와 적 공통(진입 이동, 피격, 격파, 체류형 선회·공격 예고) 프레임 수 배정.
- **Sprite-Gen의 `sprite-request.json` 규격에 맞춘 형식**으로 작성해 사양서가 곧 파이프라인 입력이 되게 하라. 사용자 보유 "perfect pixel & sprite gen" 스킬의 입력 규격은 사용자와 세션 대화로 확인해 반영.
- 용량 검증: 리스트 합산이 계획서 2.1의 스프라이트 예산 25MB 내인지 산출.

### N1-5. 파이프라인 파일럿 (P2 리스크 제거의 핵심)

- 가장 단순한 적 **a-1 1종**으로 end-to-end 실증: 레퍼런스 생성 → Sprite-Gen 처리 → 시트+manifest 출력 → 48×48 검수(그리드 정합, 팔레트 준수, 프레임 플리커 없음).
- 결과물과 소요·품질 소견을 HQ에 보고 — 이 파일럿이 통과해야 P2 에셋 양산 일정을 확정한다.

### N1-6. UI 킷 벡터 스펙 초안 (`docs/art/ui_hud_spec.md`)

- HUD 수량·정렬·치수·상태 정의를 문서로 (생성 이미지로 확정 불가한 부분). 판정 표시부는 C1 확정 대기로 비워 둔다.
