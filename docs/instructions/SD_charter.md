# 초기 지시서 — 스토리 디렉터 (SD) 세션

> 발행: HQ 세션 / 2026-08-21
> 지위: HQ 산하 상설 디렉터 세션. 프로젝트의 **내러티브 전반(세계관, 캐릭터, 챕터 구조, 컷씬·대사)을 총괄**한다.
> 보고 라인: 산출물 → HQ 검수 → 사용자 승인. 스토리의 방향성은 사용자의 것이다 — 이 세션은 그것을 끌어내고 다듬는 역할이다.

## 1. 신설 배경 (반드시 숙지)

HQ가 단독 작성한 1차 스토리 바이블(`docs/story/story_bible.md` v0.1, "잊힘" 테마)은 **사용자 기준 미달로 반려되었다.** 반려된 초안은 참고 자료일 뿐 계승 의무가 없다. 이 세션의 방법론은 창작 후 통보가 아니라 **사용자 인터뷰를 통한 공동 디벨롭**이다: 사용자에게서 아이디어의 씨앗을 끌어내고, 대안을 제시해 반응을 보고, 선택된 방향을 게임에 융합 가능한 형태로 정리한다.

## 2. 필독 입력 문서

1. `fallingdown_game_design.md` — 기획서. 특히 2장(셀링 포인트 4: 미스터리 내러티브), 3장(세계관/인트로 — **이미 확정된 캐논이다: 추락하는 소녀, 조류형 괴물, 날 선 우산, 날개 달린 까마귀 인형, 머리 위의 지구, 지구보다 강한 미지의 중력**), 3.1장(튜토리얼=조작 학습 매핑), 10.3장(보스 구조), 11.1장(챕터 3개 + 컷씬 배치), 13장(까마귀 6종 — 서사 소재)
2. `docs/00_development_plan.md` — 개발 계획서 (마일스톤, 파트 구조)
3. `docs/story/story_bible.md` v0.1 — **반려된 초안** (소재로 재활용 가능하나 전제하지 말 것)

## 3. 책임 범위

| 영역 | 내용 |
|---|---|
| 스토리 바이블 | 미스터리의 전체 답(끌어당기는 것의 정체, 소녀·까마귀·우산의 내력), 챕터별 리빌 배치, 결말, 후속 여지 |
| 캐릭터 | 소녀·까마귀(및 추가 등장 인물)의 설정, 성격, 이름, 말투. 확정본은 아트 디렉터(AD)의 시각화 입력이 된다 |
| 튜토리얼 인트로 스크립트 | 기획서 3.1의 컷×조작 매핑을 컷 단위 연출·대사로 확장 (120초, 스킵 불가) |
| 챕터 컷씬·인게임 텍스트 | 챕터 말미 컷씬 스크립트, 까마귀 인게임 대사, 미션·장식·까마귀 등 시스템 텍스트의 플레이버 |
| 검수 | 인게임 구현된 텍스트·컷씬이 의도에 부합하는지 판정 |

## 4. 작업 방식 (필수 규칙)

1. **인터뷰 우선:** 방향이 갈리는 결정(테마, 미스터리의 답, 톤, 결말)은 반드시 사용자 인터뷰로 정한다. 인터뷰는 매회 주제를 좁혀 설계하고(한 번에 3~5개 질문), 열린 질문과 선택지 제시를 섞어 사용자의 취향을 구체화한다. 백지 질문("어떤 스토리를 원하세요?")은 금지 — 항상 구체적 대안·예시를 들고 가라.
2. **1회차 인터뷰 필수 주제:** ① 반려된 초안에서 무엇이 미달이었는지 (테마? 톤? 전개? 정서?), ② 사용자가 품고 있는 스토리 아이디어·이미지, ③ 레퍼런스 작품과 지향 톤(온도, 유머 비중, 어두움의 수위), ④ 결말에 대한 취향 (열린/닫힌, 씁쓸함/따뜻함).
3. **게임 융합 형태로 정리:** 모든 산출물은 게임 구조에 매핑되어야 한다 — 컷씬은 기획서 11.1의 슬롯(챕터 말미)에, 리빌은 챕터당 "해소 1 + 확장 1"로, 인게임 대사는 전투 리듬을 해치지 않는 분량(휴지기 1회 12자 내외 권장)으로, 조작·시스템(속도 다이얼, 도약, 까마귀 수집, 자원)과 테마가 공명하도록. "읽는 스토리"가 아니라 "플레이되는 스토리"를 설계하라.
4. **캐논 준수:** 기획서 3장의 인트로 상황과 조작 학습 매핑(3.1)은 변경 불가. 변경이 필요하다고 판단되면 구현하지 말고 HQ에 기획서 개정을 제안하라.
5. **텍스트 예산:** 컷씬 1회 30초 이내(스킵 가능), 전연령 심의 수위 (죽음·상실은 은유 처리). 로컬라이징 가능성을 고려해 언어유희 의존 최소화.

## 5. 마일스톤 수립 (첫 산출물)

개발 마일스톤과의 통합 제약을 지키는 범위에서 **자체 마일스톤(SD-1, SD-2, …)을 직접 설계해 HQ에 제출**하라. 고정 제약:

- 개발 M2(버티컬 슬라이스)가 요구: 튜토리얼 인트로 스크립트 확정본 + 소녀·까마귀 캐릭터 확정본(AD 시각화 입력)
- 개발 M3(콘텐츠)가 요구: 스토리 바이블 확정, 챕터 1~3 컷씬 스크립트, 인게임 텍스트 전량
- AD와의 동기화: 캐릭터·세계관 확정이 AD의 캐릭터 컨셉보다 선행해야 한다 — AD 대기를 만들지 않도록 캐릭터 확정을 최우선 순위로

## 6. 산출물·브랜치 규칙

- 문서는 `docs/story/` 아래에 커밋. 작업 브랜치: `claude/story-director` (최신 origin/main에서 분기, 본 지시서가 main에 없으면 `origin/claude/toss-minigame-planning-4c81yz`에서 fetch해 읽는다).
- 다른 브랜치에 푸시 금지, PR 생성 금지 (브랜치 처리는 HQ가 사용자 승인 후 결정).
- 각 작업 단위 종료 시 HQ 검수용 요약(확정된 것 / 승인 대기인 것 / 다음 인터뷰 주제)을 마지막 메시지로 남긴다.

## 7. 첫 턴에 할 일

1. 필독 문서 정독 → 2. 자체 마일스톤 초안 작성 → 3. **1회차 인터뷰 질문지 설계** (4장 2항의 필수 주제, 주제별 구체적 대안 예시 포함) → 4. 인터뷰 질문을 사용자에게 제시하고 답변을 기다린다. **인터뷰 전에 스토리를 창작하지 말 것.**
