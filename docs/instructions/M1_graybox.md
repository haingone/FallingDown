# 지시문 M1 — 그레이박스 프로토타입

> 발행: HQ 세션 / 2026-08-21
> 참조: `fallingdown_game_design.md` v0.9.1 (이하 "기획서"), `docs/00_development_plan.md`
> 수행: 개발 파트 세션. 이 지시문의 범위를 벗어나는 작업은 하지 말 것. 기획서 수치와 다르게 튜닝한 값은 모두 리포트에 기록할 것.

## 목적

아트 없이 코어 루프(가속/감속 다이얼 × Z축 스와이프 × 도약)를 성립시키고, 기획서 17장 검증 항목 1~6을 실측한다. 재미가 아니라 **측정**이 목적이다 — 판단은 HQ와 사용자가 한다.

## 착수 절차

1. 앱인토스 개발자센터에서 [권장 Unity 엔진 버전](https://developers-apps-in-toss.toss.im/unity/guide/recommend-engine.html)을 확인하고 그 버전으로 프로젝트를 생성한다. 접근 불가 시 Unity 6 LTS + URP로 시작하고 리포트에 명기한다.
2. 프로젝트 위치: 저장소 루트 `game/`. 세로 고정(9:16), 모바일 터치 우선, WebGL 빌드 타깃.
3. 렌더링: URP, 라이팅 최소(툰 셰이딩은 M2 — 지금은 단색 머티리얼).

## 구현 범위

모든 수치는 기획서의 초기 기준값을 그대로 사용하되, **인게임 튜닝 패널에서 실시간 조정 가능해야 한다** (아래 "튜닝 패널" 참조).

### 1. 낙하 씬·카메라 (기획서 4장)

- 소녀 = 캡슐. 3인칭 추적 카메라, 소녀 화면 중앙, 낙하 방향을 내려다보는 구도.
- 낙하는 실제 이동 대신 배경 스크롤로 표현해도 무방 (구현 단순한 쪽 선택).
- 속도 연출: FOV 60°→72° 보간 + 방사형 속도선 파티클 밀도(프리미티브 라인이면 충분).

### 2. 낙하 속도 시스템 (기획서 7장 표 전체)

- 속도 1.0x~3.0x 연속값, 접음 +0.25x/초, 펼침 -1.0x/초.
- 배율 = 현재 속도값. 점수·깃털 획득에 곱연산.
- 최고속 콤보: 3.0x 유지 1초당 +1, 피격/베기 미스 시 리셋, 콤보 10 도달 시 배율 +0.5.

### 3. 입력 (기획서 5장)

- 스와이프/탭 분류: 이동 거리 24pt·접촉 200ms 임계. **분류 로직은 단일 클래스로 격리**하고, 매 입력의 분류 결과와 근거 수치를 로그로 남겨 오분류율을 계산할 수 있게 한다.
- 탭 = 우산 토글 (캡슐 색상 변경으로 상태 표현: 접음=빨강, 펼침=파랑).
- 스와이프 = 베기. 화면 공간 궤적이 판정 링 내 적과 교차하면 히트. 우산/검 스탠스 차이는 M1에서는 **궤적 폭 파라미터 차이로만** 구현 (우산 넓음/검 좁음, 검 연격 재판정 간격 단축).

### 4. 판정 링·적 (기획서 10장)

- 판정 링: 소녀 주변 상시 표시 링. 링 진입 적은 외곽선(또는 색상) 하이라이트 + 사운드 큐(비프음이면 충분).
- 구현할 적 (프리미티브 구체, 코드명 텍스트 라벨 부착):
  - **a-1** (통과형, 직선 쇄도, 베기 1회)
  - **a-2** (통과형, 지그재그, 베기 1회)
  - **a-3** (통과형, 5~8기 밀집 편대, 긴 스와이프 1회 다수 격파)
  - **a-4** (체류형, 선회+근접 공격, 베기 2회) — 공격 예고 0.6초 발광, 예고 중 베면 저지
  - **a-5** (체류형, 투사체 발사) — 투사체 요격 가능, 발사 후 본체 1초 노출
- 생애주기 규칙: 통과형 링 체류 0.8s@1.0x→0.3s@3.0x 선형, 체류형 공격 주기 3.0s@1.0x→1.5s@3.0x 선형, 체류형 동시 상한 4기.
- a-6, B계열, 보스는 **범위 외**.

### 5. 생존 (기획서 9장)

- HP 5칸, 접촉/공격 피해 1, 피격 무적 0.5초. HP 0 = 실패 → 즉시 재시작.

### 6. 깃털 게이지·도약 (기획서 8장)

- 하급 1기 = 5% (배율 곱 적용), 100% 시 하단 버튼 발광 → 탭 발동.
- 도약: 2.5초 무적, 밀집 방향 자동 비행, 경로상 링 진입 적 자동 격파, 도약 중 깃털 미지급.
- 종료 후: 속도 3.0x 강제 + 1초 토글 잠금.
- 까마귀 변형은 범위 외 (기본 "먹구름"만).

### 7. 테스트 스테이지

- 기획서 11.3 텐션 커브를 따르는 90초 웨이브 시퀀스 1개: 워밍업(a-1/a-2 저밀도) → 혼합(a-3 편대 + a-4) → 압박(a-5 포함 고밀도) → 최종 웨이브(최고 밀도). 하급 최소 26기 배치 (게이지 커브 검증용).
- 웨이브 사이 휴지기 2~3초. 웨이브 데이터는 코드와 분리된 데이터 에셋으로 작성.
- 중간 보스는 범위 외 — 최종 웨이브 격퇴로 클리어 처리.

### 8. HUD (기획서 15장 골격만)

- 상단 좌 HP / 상단 우 배율 숫자 / 하단 중앙 게이지 겸 도약 버튼 / 콤보 카운터. 화면 중앙 UI 금지.

### 9. 튜닝 패널 (M1 전용 디버그 기능)

- 인게임 오버레이로 다음 값 실시간 조정: 탭/스와이프 임계(24pt/200ms), 가감속률, 링 반경, 체류시간·공격주기 스케일, 스폰 밀도, FOV 범위, 히트스톱(30~50ms).
- 세션 통계 표시: 입력 분류 카운트(탭/스와이프/오분류 추정), 평균 배율, 게이지 100% 도달 시각, FPS.

## 산출물

1. `game/` Unity 프로젝트 (저장소 커밋, `.gitignore`에 Library 등 제외).
2. WebGL 빌드 산출물 또는 재현 가능한 빌드 절차 문서 (`game/BUILD.md`).
3. **튜닝 리포트** `docs/reports/M1_report.md`:
   - 기획서 17장 항목 1~6 각각에 대한 실측/소견 (항목 7 용량은 엔진 런타임 기준치만 기록)
   - 오분류율 실측치와 최종 임계값
   - 90초 시퀀스에서 게이지 100% 도달 시점 실측 (기획서 11.3의 "최종 웨이브~보스 구간 도달" 성립 여부)
   - 기획서 기준값과 다르게 튜닝한 모든 수치의 목록과 사유
   - 모바일 브라우저(가능하면 실기기) FPS 실측
   - 다음 마일스톤에 넘길 기술 부채·우려 사항
